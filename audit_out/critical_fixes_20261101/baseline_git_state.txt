## What happened in between

The first agent launch did not set worktree isolation, so five agents shared this checkout. One agent
ran `git switch -c` here, and another stashed the five modified files to get a clean baseline:

```
stash@{1}: On main: pre-existing unrelated worktree changes
v8-next/src/v8_next/adapters/expert_strategy.py
v8-next/src/v8_next/app/cli.py
v8-next/src/v8_next/audit/pipeline.py
v8-next/src/v8_next/research/arms.py
v8-next/src/v8_next/research/runner.py
```

Recovery, in order: halted all five agents (no commits existed, so no branch was polluted), switched
the checkout back to `main`, `git stash pop` on that entry, moved every remaining agent into its own
worktree. Verified afterwards that `git status --porcelain` matched the pre-goal observation above.

A second stash (`issue-495 g3 work in progress`) held that agent's own WIP; it was applied into
`v8-wt-495`, the resulting work was committed as `34f00b7`, and the stash entry was dropped once the
work was safely in git. No stash entries remain.

## Lesson

`isolation: "worktree"` must be set on every parallel agent that may run git. It is not the default,
and the failure mode is silent: the tree moves under agents that are still working.
