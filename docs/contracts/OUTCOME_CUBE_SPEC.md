# Outcome Cube Specification

**Status:** PROVISIONAL_DECISION. Sections 2-3 and 6 describe the instrument as
**built** in V8.0 (`tools/regret.py`, admitted by D-071) and are
PROJECT_EVIDENCE_SUPPORTED. Sections 4-5 are the V8.2 execution model (D-081)
and are DESIGN_INFERENCE until measured. Every value the cube produces is
MODEL_DERIVED and carries no economic authority (rule 12).

## 1. What the cube is

For each Candidate `C`, the Outcome Cube holds the replayed outcome of every
**legal alternative action** the system could have taken on that Candidate,
under one versioned Replay Model:

```text
cube[C, a] = Replay(C, a, M)     for every a in A(C)
```

It is a measurement instrument layered **on top of** the V8 decision path, not
a part of it. The cube:

- reads a completed Lab store; it never re-runs the decision loop;
- never creates a Candidate, never mutates one, never touches an Expert, a
  geometry, or a verdict (`RECOVERABLE_REGRET_PROTOCOL` §2);
- reports refusals rather than manufacturing values it cannot justify.

## 2. The legal action manifest `A(C)`

Generated by `generate_legal_actions(actual_geometry)`. Structure, in order:

| Index | Action | Provenance |
|---|---|---|
| 0 | `NO_TRADE` | `DECLARED_VARIANT` |
| 1 | the **actual** action, seeded directly from the frozen draft geometry | `ACTUAL` |
| 2.. | declared geometry variants over the continuous grid | `DECLARED_VARIANT` |

The actual action is element 1 **by construction**, not by a grid that happens
to contain it. This is what makes `a_actual ∈ A(C)` a structural guarantee
rather than a coincidence, and it is what allows the gap in §6 to be
non-negative by definition.

Declared grid:

```text
CONTINUOUS_AXIS_GRID = {'target_r': (1.0, 2.0, 3.0), 'expiry_bars': (8, 24, 48)}
```

giving `|A(C)| <= 11` after de-duplication against the actual action.

**Structurally excluded axes.** `direction` and `pyramid_add_rules` are not
variant axes. Flipping direction is not an alternative action on the same
Candidate — it is a different Candidate, and admitting it would let the
evaluator invent proposals the Expert never made. A Candidate whose geometry
touches an excluded key gets `NO_TRADE` plus its actual action only.

Each manifest carries `manifest_id` (a hash of the action set and the generator
version), `cardinality`, `continuous_axes_sampled`, and `generator_version`, so
a cube row is always interpretable against the exact action universe that
produced it.

## 3. Cell status: refusal is a first-class outcome

A cell that cannot be honestly evaluated is **labelled, not filled**.

| Status | Meaning |
|---|---|
| `OK` | the replay produced a real outcome |
| `CENSORED` | the position had not terminated when the tape ended |
| `UNDEFINED_FUTURE` | fewer than `MIN_FUTURE_BARS` bars exist after the entry bar |
| `NOT_EVALUABLE_ACTION` | the action is not evaluable for this Candidate |
| `NO_ENTRY` | the action's entry never filled |

`UNDEFINED_FUTURE` exists because the simulator, given an empty or
entry-only tail, returns a manufactured `EXPIRY` value (measured: `-cost` for an
entry-only tail, `0.0` for an empty one). Accepting that number would put a
fabricated outcome into a regret table. The instrument refuses instead.

Every downstream statistic must abstain on any non-`OK` cell that could be the
maximizing cell; it may not silently drop it and take the max over the
remainder.

## 4. V8.2 execution model: streaming reduction

The cube is a **computation**, not necessarily a stored table.

```text
for each candidate C:
    for each action a in A(C):
        outcome = ReplayKernel(&Dataset, C, a)      # bounded window
        RegretAccumulator.absorb(C, a, outcome)     # in memory
emit reduced tables
```

Materializing every cell costs, at the research target, ~9.9M rows/symbol —
~600 GB across 100 symbols as JSONL (`LEDGER_FORMAT_SPEC` §7) — and then reads
all of it back to compute per-Candidate reductions that need only a few
accumulators per Candidate.

**Rule.** At `VALUES` tier the cube is reduced in flight and only the reduced
tables are persisted. At `FULL` tier (certification and promotion boundaries)
the cube is materialized in full, columnar, with run-constants hoisted.

The reduction must be **order-independent and exact**: accumulators are
per-Candidate maxima, the actual-action value, the `NO_TRADE` value, and cell
counts by status. No accumulator may depend on the order in which actions are
absorbed, or the value would depend on scheduling — which
`PARITY_AND_IDENTITY_SPEC` G5 forbids. Ties are never broken (§6).

Streaming is what keeps verdict statistics in the analysis plane: after
reduction the data crossing the plane boundary is order 10^4-10^6 numbers, not
10^7 rows (`COMPUTE_CORE_SPEC` §7).

## 5. The bounded-window rule

> **A replay cell is passed `(&Dataset, start, end)` and may read no bar
> outside `[start, min(end, start + expiry_bars + 1)]`.**

Measured on the V8.0 implementation, which slices the entire remaining tape per
cell (`tail = bars[i:]`):

| | per cell |
|---|---|
| tail slice + payload/time rebuild | 71.8 us |
| the replay arithmetic it feeds (60-bar window) | 6.4 us |

~92% of the cell cost is copying bars the cell can never read
(`PERFORMANCE_AUDIT_V82` §6). At 246,884 cells per symbol-year this is 21.6 s
versus 1.6 s.

The rule is normative for both implementations. It is stated here rather than
left to the compute core because it is a property of the **cell contract** — a
cell's read set is determined by its declared geometry — not an optimization.

## 6. The gap, and what it is not

Per Candidate, the legal hindsight gap is

```text
gap(C) = max{ Replay(C, a, M) : a in A(C), status(C, a) = OK }  -  Replay(C, a_actual, M)
```

which is non-negative by construction, since `a_actual ∈ A(C)` (§2). Ties are
reported, never broken. The computation abstains whenever a non-`OK` cell could
have been the maximizer.

**What the gap is:** value left on the table inside the represented Candidate
and action universe, under a costed, versioned Replay Model.

**What the gap is not:** evidence that a decision-time-realizable policy could
have selected the better action. Hindsight opportunity is not recoverable
opportunity. That question is answered — if at all — only by the
recoverability phase against a declared decision-time policy class
(`RECOVERABLE_REGRET_PROTOCOL` §5), and its answer to date is a
loss-reduction result with negative absolute utility, not a profitability
finding (D-073).

## 7. Cheap executable tests

1. `a_actual` is element 1 of every manifest, and `Replay(C, a_actual, M)`
   reconciles with the observed ledger outcome to 1e-12.
2. A Candidate with an excluded geometry key yields exactly two actions.
3. A cell instrumented with a bar-read counter never exceeds
   `expiry_bars + 1` reads.
4. A Candidate born within `MIN_FUTURE_BARS` of the tape end yields
   `UNDEFINED_FUTURE`, never a numeric outcome.
5. `gap(C) >= 0` on every `COMPUTED` Candidate; a negative gap is a defect, not
   a finding.
6. Streaming reduction and full materialization produce identical reduced
   tables on the same fixture (the `FULL`/`VALUES` equivalence gate).
7. Absorbing a Candidate's actions in reversed order produces identical
   accumulators.
