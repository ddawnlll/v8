## Last design-freeze decisions

- Baseline parity preserves the chosen pinned V8 strategy and its legacy gates; **new** expert/MarketBelief routing stays OFF.
- `DecisionPolicyV0` is pure and entry-only. Atomically reserve intent/outbox only in the existing native execution writer after risk validation.
- Partial fill may mean simultaneous exposure + pending order; native exit/protection callbacks continue regardless of V0 receipt.
- Native safety and audit source findings are **repair issues**, not proof of runtime resolution.
- Economic gates are scoped by `claim × producer × dataset × execution_profile`; #491 cannot become an all-purpose development blockade.
- From now on: P0-A symbol map, P0-B used-path repair + independent oracle, P0-C mechanical parity; then only a preregistered challenger.

## Implementation protocol

1. Read V8 active boundary; produce local HEAD/D4 implementation inventory with symbols, test paths, and actual defects before coding.
2. Confirm historical audit issues on the currently pinned native replay and independent golden/fault-injection checks.
3. Approve only the `DecisionPolicyV0` mechanical vertical slice first; do not implicitly activate learned routing, new entry logic, stop policy, portfolio rotation or the Pi loop.
4. Require an owner decision for each versioned policy change and separate mechanical, accounting, scientific, and deployment authority.
5. `Kaizen` is a supplementary offline research capability; no LLM calls in trading callbacks.

**Never** treat this monograph as an instruction to merge all the proposed features in one PR.
