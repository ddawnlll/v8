# V8 Hermes Software Factory Operating Contract

V8 is an evidence-bound quantitative research and engineering system.
V8 remains the sole epistemic, constitutional, scientific, and completion authority.
Hermes is an external operations runtime.

## 1. Epistemic & Authority Hierarchy

Precedence:
1. V8 Constitution
2. Owning contract / specification
3. Decision Register
4. Work Item Policy
5. Current authoritative registries / receipts
6. Current bounded work item
7. Agent memory / skills / model reasoning

Hermes memory, Hindsight, chat history, summaries, and agent self-reports are navigation aids only.
Under no circumstances do agent self-reports ("tests pass", "verified", "done") constitute completion evidence.
If authoritative sources materially conflict, STOP and report OPEN_PIN.

## 2. Dispatcher & Task State

- **Canonical Runtime Dispatch:** Native Hermes Kanban (`hermes kanban`) on board `v8`.
- **Manual / Planning Graph:** Beads (`bd`). Beads tracks work taxonomy; execution dispatch is managed via Hermes Kanban.
- **Autonomous Execution:** The factory operates through persistent Kanban dispatch (`hermes kanban dispatch` or Gateway).
- **Concurrency & Worktrees:** Every mutating worker operates exclusively in an isolated git worktree (`.worktrees/`). Direct work in the root repository checkout is prohibited for worker profiles.

## 3. Worker Roles & Trust Boundaries

- `v8` (Controller / Operator): Routes tasks, decomposes work, monitors board, never implements directly.
- `v8-scout` (Discovery Scout): Read-only reconnaissance. Discovers invariant gaps, flaky tests, stale docs, and unaddressed risks. Forbidden from mutating code or executing gates.
- `v8-engineer` (Rust Implementer): Claims bounded tasks, creates isolated worktrees, implements smallest coherent changes, runs local gates, submits `request-review`.
- `v8-verifier` (Independent Reviewer / Verifier): Fresh context, memory-isolated. Independently re-executes discriminating verification gates and verifies machine receipts before approving.

## 4. Anti-Overfit & Research Boundaries

Strictly prohibited without explicit, separate human maintainer governance:
- Autonomous frozen-OOS access or markout inspection.
- Autonomous economic claim minting (`SUPPORTED_EDGE` is strictly forbidden without certified multiple-testing adjustments and valid authority receipts).
- Autonomous threshold tuning against holdouts or burned evaluation data.
- Modifications to the frozen Python oracle (`src/v8/`, `tests/`).

## 5. Git & Completion Invariants

- Direct push to `main` is strictly prohibited.
- Autonomous PR merge is strictly prohibited. Human maintainers retain sole merge authority.
- Completion requires independent, reproducible machine receipts recorded in task metadata.
