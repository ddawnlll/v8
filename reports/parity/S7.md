# S7 parity gate — Verdict statistics + report/audit artifacts

**Stage:** COMPUTE_CORE_SPEC §8 S7 · **Date:** 2026-08-12
**Gate:** the `verdict` subcommand's statistics match the frozen oracle
`src/v8/statistics.py` bit-for-bit on a fixed episode series + seed; the
report artifact round-trips through the V8.2 reader; the S7 audit flags a
report artifact that references an older tape (issue #123 freshness).
**Oracle tree hash (frozen):** `2854f8c30fe59a25ef617d0357cd2fc71faa9b0b`.

## What was built

- `v8-core/src/statistics/mod.rs` — the S7 `verdict` subcommand (issue #128
  wiring): reads one evaluation request (an episode net_R series directly
  `{net_r: [...], config: ..., seed: ...}`, a multi-config family map
  `{configs: {...}}`, or the cube-reduced artifact `{out_dir: ...}` via the
  COMPUTED `legal_hindsight_gap` column) and prints the verdict JSON over the
  block-bootstrap Reality-Check (`reality_check.rs`, issue #128), the
  Appendix A detrended-null placebo invariant (`detrended.rs`, issue #124),
  and the METH-2..6 surface (`remaining.rs`, issue #129): permutation
  Reality-Check, bootstrap CI, effective independent episodes, regime slices,
  streak-vs-null, practical significance, expected false positives, effective
  search size. Every draw is seeded from the request (never the wall clock,
  G5); every oracle `ValueError` fails the subcommand closed. Sections whose
  inputs the request does not supply are emitted as `{"run": false}` so the
  schema is stable. The top-level claim stays `NO_ECONOMIC_CLAIM` (rule 12).
- `v8-core/src/report.rs` — the report driver (issue #126) extended additively:
  `verdict_path` consumes the verdict subcommand's JSON output into the
  driver summary (the report artifact's own `verdict` stays
  `NO_ECONOMIC_CLAIM` — a statistics p-value is not an authority receipt),
  and `audit_report` audits an existing report artifact against the current
  tape/producer instead of writing a new one — the path by which the S7
  audit's freshness check flags a stale artifact (issue #123).

## Known limitations

- The parity fixture is a single-configuration family (the verdict's series
  mode). Multi-config WRC families resolve in sorted-name order (G4
  determinism) — a mean TIE between configurations resolves toward the
  lexicographically first name rather than the Python dict's insertion order;
  the unit tests pin single-config behavior bit-for-bit.
- The cube-reduced source mode is exercised at the Rust unit level (a
  hand-built `cube-reduced.v82` with COMPUTED + abstained rows); the parity
  harness feeds the verdict an explicit episode series, which is the contract
  the task's parity test specifies. The real-tape cube → verdict path is the
  certification boundary and is not part of this gate.
- The report round-trip covers the minimal (ledger-absent) mode end to end;
  the ledger-bound report path is covered by the report.rs unit tests
  (`report_audit_battery_all_six_pass_on_fresh_report`, `audit_flags_a_replaced_ledger`).
- A `verdict_path` that fails to parse fails the report run closed (fail
  closed, OPERATIONS_SPEC §5) — the driver never silently drops a consumed
  verdict.

## Not claimed

No economic claim and no speed claim. The S7 gate is correctness: the verdict
statistics are bit-identical to the frozen Python oracle on the fixture, the
report artifact round-trips, and the audit's freshness check demonstrably
flags a stale artifact. The verdict claim remains `NO_ECONOMIC_CLAIM`; an
authority receipt is a separate, future gate.
