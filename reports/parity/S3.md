## What was built

- `v8-core/src/regret.rs` — the `LegalActionManifest` (NO_TRADE at element 0,
  the ACTUAL action at element 1 by construction, the declared grid
  `target_r (1,2,3) x expiry_bars (8,24,48)` de-duplicated by action id,
  `pyramid_add_rules` excluded → cardinality 2), the cell-status classifier
  (OK / CENSORED / UNDEFINED_FUTURE / NOT_EVALUABLE_ACTION / NO_ENTRY,
  `MIN_FUTURE_BARS = 1`), and the per-Candidate reduced record + `compute_gap`
  (best over OK cells incl. NO_TRADE, `GAP_TIE_EPS = 1e-12` ties reported
  never broken, abstain on CENSORED / no-OK / actual-cell-not-OK).
  Action and manifest identities are V8.2 bit-encoded (D-079).
- `v8-core cube <request>` subcommand: streams one Candidate at a time —
  manifest → replay each cell via the ReplayKernel (S2) → classify → reduce
  in memory → emit the `cube-reduced` artifact. The cells are never
  materialized across Candidates (D-081).

## Known limitations

- The reduced-table comparison covers the value fields the Python evaluator
  emits (RegretRecord); the per-cell counts-by-status and NO_TRADE value that
  the Rust streaming reducer also carries are extra (checked for internal
  consistency, not against the Python side — the Python RegretRecord does not
  expose them).
- The fixture is single-symbol synthetic (400 bars). The real-tape cube is
  the certification boundary (FULL tier, OUTCOME_CUBE_SPEC §4) and is not
  part of this gate.
- `FILL_AT_LIMIT` grid cells never fill on the fixture (no registered Expert
  declares a limit) → NOT_EVALUABLE_ACTION, matching the Python side.

## Not claimed

No speed claim. The S3 gate is correctness — the streaming reduction is
bit-identical to the Python evaluator's full-materialization reduction on
every Candidate, and the refusal semantics (UNDEFINED_FUTURE, abstentions)
agree.
