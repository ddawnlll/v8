## What was built

- `v8-core/src/experts/predicate.rs` — the compiled `still_valid` IR
  evaluator: `compare` (with FLIP_ON_SHORT), `asym_compare` (direction-
  asymmetric constants: rsi_stoch_reversion, macd_stoch_trend),
  `all_of`/`any_of`, ordered `dispatch` (with geometry-value equality cases),
  and `guard` (whole-condition fail-open). Operands: `live`, `live_window`
  (donchian channel), `ref`, `ref_dir` (direction-selected frozen ref),
  `window_agg` (with INCLUSIVE/EXCLUSIVE end), `window_agg_dir`, `mean_of2`
  (ichimoku kijun), `const`. Fail-open on any absent operand is normative.
- `v8-core/src/simulator.rs` — the `ReplayKernel`: a byte-for-byte port of
  `sim.run`/`_exit_loop`/`step` (R-multiples, `risk_unit`, `validate_geometry`,
  FILL_AT_BAR_CLOSE/LIMIT, funding `SETTLEMENT_BEFORE_ORDERS` with the scalar
  and schedule paths, STOP_FIRST ambiguity, gap-through stop at the worse of
  barrier and open, THESIS_INVALIDATED/TIME_EXIT/EXPIRY, EXEC-1..6 management,
  `net_r = realized_r + remaining*(sign*(exit-entry)/unit) - cost - funding`).
  The kernel reads `&bars[start..end]` with `end = min(end, start+expiry+1)`
  (OUTCOME_CUBE_SPEC §5 bounded windows) and evaluates the compiled predicate
  from the feature store at the stepped bar — no Python callback (D-078).
- `tools/predicate_ir.py` — the declarative `still_valid` → IR compiler for
  all 28 registered Experts, transcribed verbatim from the sources, emitted
  as canonical JSON (the V8.2 bit-encoding of those bytes is the predicate
  identity; the vocabulary is closed per E5).
- `v8-core predicate-check <ir> <cases>` (batch) and `v8-core replay
  <request>` subcommands.

## Determinism findings

1. **serde_json's default float parser is NOT correctly rounded** — measured:
   `"0.9632136759338213"` parses to a value 1 ulp below CPython's parse. Every
   request-side float (geometry refs, atr_ref, manifest) would silently drift
   and break value parity. Fixed by enabling serde_json's `float_roundtrip`
   feature. (The tape itself is parsed by `jsonx`, which uses Rust's
   correctly-rounded `f64::from_str`, so tape values were never affected.)
2. **Fail-open semantics are not uniform.** Two shapes exist in the sources:
   per-operand fail-open (the dominant `close vs frozen ref` form) and
   whole-condition fail-open (trend_pullback_depth, rsi_stoch_reversion
   variant b, bollinger_reversion's close pre-check, gap_exhaustion's
   either-ref check) — the code returns `True` before the AND if ANY operand
   is absent. The IR captures the distinction with the `guard` node.
3. **Violation-form boundaries.** fib_rsi_bb_confluence's prior_low_ref rule
   dies on `c < ref`, so the valid form is `c >= ref` (GTE — the equality
   boundary HOLDS); the 3sd rule dies on `c <= ref3`, so the valid form is
   `c > ref3` (GT). Using GT for both broke the boundary grid point.

## Known limitations

- The donchian `responsive`/`significant_extreme` exit kinds (module-local
  subclasses, not exported by the registry) are compiled in the IR table but
  not exercised by the E1 grid (the exported `DonchianBreakoutExpert` is the
  `channel` exit kind). Their still_valid surface is transcribed from the
  sources; they are exercised only if a fixture produces such a candidate.
- The E4 population is single-symbol synthetic (400 bars). The real-tape
  candidate population parity is exercised at S3 (cube/reconciliation), where
  the same kernel replays against the observed ledger.
- `FILL_AT_LIMIT` is ported but not exercised (no registered Expert declares
  `limit_price`; `tools/regret.py`'s cube marks it NOT_EVALUABLE_ACTION when
  it never fills).

## Not claimed

No speed claim. The S2 gate is correctness — every replayed outcome is
bit-identical to the Python-closure outcome on the candidate population, and
every compiled predicate is grid-equivalent to the Python method it replaces.
