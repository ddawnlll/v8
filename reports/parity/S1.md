## Determinism findings (the substance of this gate)

Bit-parity against CPython 3.14 forced three portability discoveries, each
now pinned by a Rust unit test:

1. **CPython `sum()` is compensated summation, not a left fold.** CPython
   3.12+ `sum()` over floats uses the `_PyFloat_Fsum` partials algorithm
   (identical to `math.fsum`). A left fold drifts by ulps on ~20-element
   windows (measured). `state::fsum` is a verbatim port including the special
   final fold (largest partial first, stop at the first inexact addition) and
   the half-even tie fix (`sum([1e-16, 1, 1e16])` must round up to two). All
   `sum(...)`-mirroring reductions (mean, std_pop, ATR, RSI seed, ADX seed,
   CCI, stoch %D) go through it; `+=`-loop reductions (vwap, cmf, obv, adl)
   stay plain folds. Pinned by a 17-case battery captured from CPython 3.14.
2. **CPython `x ** 2` is libm `pow(x, 2.0)`, not `x * x`.** They differ by
   1 ulp on some values. Rust `powf` calls the same libm, but LLVM folds
   `pow(x, 2.0) -> x*x` in release — `std::hint::black_box` keeps the
   exponent opaque so the libm call survives (COMPUTE_SCHEDULING_SPEC §5: an
   optimization may not change a value).
3. **CPython `x ** 0.5` is libm `pow(x, 0.5)`, which differs from `sqrt(x)`
   by 1 ulp on some values** (measured on the real tape's volume window:
   `40b37cca79af14c9` vs `...ca`). `_std_pop` finishes with `** 0.5`, so the
   Rust side uses `powf(0.5)` (black_box'd).

Also fixed en route: two usize underflows (`i - period + 1` → `i + 1 -
period`) that only panic in debug builds but silently wrap in release — now
correct in both.

(series cache), the same one the lab uses.

## Known limitations

- Multi-interval `build_multi_state` (aggregate → namespaced `{sym}.{tf}.{name}`
  features) is not yet in the S1 gate; the base-interval state (which
  `build_multi_state` delegates to unchanged) is fully covered. The aggregate
  port lands with the S4/interval work.
- The `history` feature and the other structured features (fib_levels,
  pivot_points_day, consolidation_range, gap_levels) are compared via a
  canonical JSON carrier column; the value comparison parses and bit-compares
  element-wise.
- `input_lineage_hash` (per-feature) is computed for identity semantics but
  not yet emitted in the artifact; it is excluded from parity by §3.

## Not claimed

No speed claim. The S1 gate is correctness — every feature value on every bar
is bit-identical to the frozen Python oracle. PERFORMANCE_AUDIT_V82 figures
remain the comparison baseline for any future measurement.
