# S0 parity gate — parity harness + Dataset ingest

**Stage:** COMPUTE_CORE_SPEC §8 S0 · **Date:** 2026-08-11
**Gate:** the tape round-trips and the three clocks (event / available /
ingested) are preserved, on every row of every fixture.
**Oracle tree hash (frozen):** `2854f8c30fe59a25ef617d0357cd2fc71faa9b0b`
(`git rev-parse HEAD:src/v8`) — any change to `src/v8` invalidates this result.

## What was built

- `v8-core/` — the Rust compute plane workspace (one binary, modules; the
  no-callback invariant D-078 holds: it links no Python runtime).
  - `src/hash.rs` — V8.2 canonical bit encoding (D-079): f64 → 8 IEEE bytes
    LE with NaN normalized to one declared payload, `-0.0` distinct from
    `0.0`, strings length-prefixed, composites tagged; digest SHA-1.
  - `src/data.rs` — `Dataset`: JSONL tape ingest, `_validate_tape_rows`
    mirrored verbatim (G6), (source, event_id) dedup like the store inbox,
    canonical replay order `(event_time, available_time, venue_sequence)`,
    per-symbol columnar closed klines (one allocation per symbol).
  - `src/evidence.rs` — columnar artifact writer (LEDGER_FORMAT_SPEC §3-4):
    magic `V82LDRG1`, JSON header, per-column validity bitmask + fixed-width
    IEEE-754/two's-complement values + dictionary-encoded strings; no decimal
    float text in numeric columns; no wall clock (G4 byte-identity).
  - `src/jsonx.rs` — Python-`json`-compatible tape line parser: CPython
    `json.dumps` emits `NaN`/`Infinity` as bare literals that strict JSON
    rejects; the parser records them with their JSON path so the oracle's
    classification survives (a NaN OHLC must raise "non-finite OHLC", not a
    generic parse error).
  - `src/main.rs` — `v8-core ingest <request.json>`; subcommands are the
    separately-dispatchable kernels of later stages (COMPUTE_SCHEDULING_SPEC
    §2). `threads`/`engine` are scheduling details, never in any hash.
- `.cargo/config.toml` — `--fp-contract=off` (FMA contraction off, G5; CPython
  does not fuse multiply-add).
- `tools/v82_reader.py` — analysis-plane reader for `.v82` artifacts.
- `tests/parity/` — the Python-driven harness (conftest builds the binary
  once, pins the oracle tree hash; runner writes fixtures, invokes the binary,
  bit-compares).

## Determinism

- Release profile: `codegen-units=1`, LTO, `--fp-contract=off`; build warnings
  0.
- Artifact bytes contain no wall clock; two identical requests write
  identical files (G4 verified).
- No Python runtime linked; no callback path exists (`src/main.rs` has no FFI
  surface).

## Known limitations

- The `dataset` artifact echoes each row's `payload` as canonical JSON text
  (the tape has variable-shaped payloads across channels); the parity harness
  compares parsed *values*, and the tape-echo column is an input echo, not a
  research value column. Value-bearing research artifacts (states/outcomes/
  cube, S1+) use numeric f64/i64 columns exclusively.
- The lenient tape parser normalizes `-Infinity`/`Infinity`/`NaN` detection to
  the classification level; messages match modulo float rendering (documented
  above).
- Real-tape fixtures are read from `research/tape/` (gitignored, reproduced
  from public archives) — present on this machine; a clean checkout requires
  re-downloading them before the real-tape tests can run.
- `test_real_multi_symbol_tape` uses a 25,000-row slice of the 394,545-row
  multi-symbol tape to keep the gate fast; the full tape is covered by the
  same code path (single-symbol fixture runs the full 9,948-row tape).

## Not claimed

No speed claim is made. The S0 gate is correctness — the tape round-trips and
the clocks are preserved. PERFORMANCE_AUDIT_V82 figures remain the comparison
baseline for any future measurement.
