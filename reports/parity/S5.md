## What was built

- `v8-core/src/evidence.rs` (issues #108, #109):
  - `ArtifactTier` (`IDENTITY_ONLY | VALUES | FULL`) and `FieldTier`
    (`IdentityOnly | Values | Full`), with `rank()` ordering
    (`IDENTITY_ONLY < VALUES < FULL`) and the reader-side check
    `ArtifactTier::can_serve(field_tier)`. The tier is recorded in the header
    and is therefore part of the artifact identity — a `VALUES` artifact can
    never be mistaken for a `FULL` one (LEDGER_FORMAT_SPEC §5).
  - The **tier-honesty rule** (§4): `Artifact::add_field` rejects any field
    whose `FieldTier` is above the artifact's tier with an explicit
    `TierViolation { field, field_tier, artifact_tier }` — a `VALUES`
    artifact cannot carry a `FULL`-only materialized derivative (lineage
    hashes, per-feature clocks, expanded history), an `IDENTITY_ONLY`
    artifact cannot carry an information column. The failure is explicit,
    never a silently downgraded field or an empty column. The raw
    `add_column` primitive stays for pre-validating callers (the S0 dataset
    path).
  - `RunConstants` — the §3 key set in §3 order (`data_hash`, `code_hash`,
    `config_hash`, `simulator_hash`, `risk_gate_hash`, `evaluator_version`,
    `platform`, `utility_unit`, `cost_form`, `slippage`,
    `action_manifest_id`), bound into every header by the per-kind
    constructors `state_artifact` / `candidate_artifact` / `outcome_artifact`
    / `evaluation_artifact` / `cube_artifact` together with the per-artifact
    bindings `symbol`, `interval`, and the `v8-core/<version>` generator tag
    (also run-constants, §2). No wall clock ever enters an artifact.
  - The LEDGER_FORMAT_SPEC §8 cheap-test battery
    (`run_ledger_battery` → `v8-core ledger-check`): round-trip,
    header-completeness, byte-stability, tier-honesty, no-decimal-floats
    scan, retention — each against a deterministic self-built 3-row
    `VALUES`-tier state fixture whose stored `state_id` is the SHA-1 of its
    regenerable fields (`as_of | close`), so §8 test #1's "regenerated
    field's hash equals the stored identity" is exact.
- `v8-core/src/cache.rs` (issue #107): the content-addressed DAG cache. The
  missing node is cube level — `(candidate_id, action_id, simulator_hash,
  data_hash) -> outcome`. The canonical string key
  `{candidate_id}|{action_id}|{simulator_hash}|{data_hash}` is hashed to a
  SHA-1 content address; entries are addressable by that digest, never by a
  run-global id. `CacheStore` is an in-memory map plus an append-only JSONL
  log (`cache.jsonl`), so a later process hits the same entries. Insert
  appends to the log first, so a failed write leaves the in-memory map
  untouched (fail closed).
- `v8-core cache-check <request.json>` (S5 gate driver): loads a request,
  derives the cube key, then simulates a **miss** (compute + store + write)
  and a **hit** (a fresh `CacheStore` over the same JSONL log — what a
  second request in a fresh process would do — retrieve + write) and asserts
  the two artifact fingerprints are identical. The gate claim
  (COMPUTE_CORE_SPEC §8 S5): a cache hit never changes the ledger identity.
  `compute_outcome` is a deterministic pure function of the key and digest,
  standing in for Replay + CubeReducer; the identity gate only needs the
  outcome to be a pure function of the key, so a recompute and a cache hit
  agree.
- `tests/parity/test_parity_s5.py` (issue #109): runs the shipped binary end
  to end — the §8 battery via `v8-core ledger-check` (with a request-provided
  `out_dir`/`tape_hash`, self-built default, and a fail-closed malformed
  invocation).

| #2 header completeness | removing any one run-constant (or `hash_encoding`/`tier`) fails closed with the missing key named — never a row with a missing field | `battery_header_completeness` + `removing_any_run_constant_fails_closed` | PASSED |

| #4 tier honesty | an `IDENTITY_ONLY` artifact cannot satisfy a reader that requires values; the failure is explicit, never an empty column | `battery_tier_honesty` + `values_artifact_rejects_full_only_field` / `identity_only_artifact_rejects_information_field` | PASSED |
| #5 no decimal floats | a scan of every numeric value region finds no text encoding of a float (region-scoped: the header's run-constant decimal, e.g. `slippage 0.5`, is not a hit) | `battery_no_decimal_floats` + `numeric_value_regions_contain_no_decimal_float_text` | PASSED |

The battery fixture is a deterministic 3-row `VALUES`-tier state artifact
(`FIXTURE_BARS = 3`), written through the production tier machinery
(`state_artifact` + `add_field`), so tier honesty and header completeness
run on the real write path. Its `state_id` is `sha1(as_of | close)`, where
`close` is a pure function of the as-of clock — the fixture's stand-in for
"a dropped field regenerated from (tape, code)".

## Known limitations

- **The cache is not wired into the request loop.** `runloop.rs`'s cube
  reduction (`write_cube_reduced`) writes its `cube-reduced.v82` artifact via
  `regret.rs` directly and never consults `CacheStore`; the cache is
  exercised by its own unit tests and the `cache-check` driver, which
  simulates both paths with a stand-in outcome function. Wiring the loop to
  the cache is the S4 integration.
- The §8 battery runs against a self-built 3-row fixture, not a real tape
  population. Real-tape ledger writes and their audit are the certification
  boundary (FULL tier, LEDGER_FORMAT_SPEC §5-6) and are not part of this
  gate.
- The `cache-check` gate proves identity stability for the key shape it
  derives from the request (`candidate_id|action_id|simulator_hash|
  data_hash`); the real Replay + CubeReducer substitution for
  `compute_outcome` must reproduce this purity-of-function property when the
  loop is wired at S4.

## Not claimed

No speed claim. The S5 gate is identity — a cache hit never changes the
ledger identity, and the ledger-format contract is executable, not prose.
PERFORMANCE_AUDIT_V82 figures remain the comparison baseline for any future
measurement.
